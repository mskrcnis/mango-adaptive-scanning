# Offline scanner application

After the complete workflow has created and verified `results/frozen/manifest.json`, launch `python3 run_project.py app` and open `http://127.0.0.1:8765`. Choose the real development example or manual single-channel input, start the scan, and supply only the requested LED reading. The display updates the dry-matter estimate, acquired pulse count, next requested LED, and decision trace. Export the trace as JSON. The app binds only to the local loopback address.

Run `python3 run_project.py replay --example` for the same development replay in the terminal. Run `python3 run_project.py replay --manual` to enter requested channel readings without loading a full-spectrum CSV. The manual input is reference-normalized apparent absorbance for the requested simulated channel; a physical driver would implement the same `read_channel(led_id)` interface. Both modes use the frozen primary bank, calibrated controller and development-targeted scientific threshold. The demo fixture contains no laboratory assay or external-season outcomes.

The automated app check starts an ephemeral local server, visits the HTML route, completes replay through the HTTP API, exports the trace, repeats the acquisition through manual API input, and compares both traces exactly with the CLI simulator. It also tests invalid readings, hidden-channel invariance, termination and repeated-pulse prevention. Results are written to `results/app_test.json` and the test server is then closed. All reported pulse counts are simulated acquisition effort; no physical energy or hardware scan-time claim follows from this application.
